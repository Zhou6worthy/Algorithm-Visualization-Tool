# M3-5 开发指令：多测试用例管理与真实 ExecutionTrace / AnimationTrace 切换

## 一、阶段目标

本轮实施范围严格限定为：

**M3-5：多测试用例管理与真实执行轨迹切换。**

当前系统已经具备：

- M1：真实代码执行与 ExecutionTrace；
- M2：AnimationTrace 与 Two Sum 教学演示；
- M3-1：VisualPlan、ComponentRegistry、基础组件协议；
- M3-2：CodeVisualizer 抽取；
- M3-3：ArrayVisualizer、HashMapVisualizer、VariableVisualizer 抽取；
- M3-4：TwoSumVisualProfile、VisualAssembler、VisualPlan 驱动装配。

目前系统主要围绕单个 Two Sum 测试用例生成演示。

本轮目标是：

**允许用户为一道算法题提供多个测试用例，系统分别执行每个用例、生成独立的执行轨迹和动画轨迹，并支持在不同用例之间切换。**

核心流程：

用户输入多个测试用例
→ 测试用例管理
→ 分别执行 AC 代码
→ 每个用例生成独立 ExecutionTrace
→ 每个用例生成独立 AnimationTrace
→ 教学演示系统加载指定用例
→ 现有视觉组件展示对应状态。

本轮只完成多测试用例和真实 Trace 切换，不开发完整课堂播放器。

## 三、M3-5.1：测试用例数据模型

建议新增：

`algoviz/protocol/cases.py`

定义以下数据模型。

### 1. TestCaseSpec

描述一个测试用例。

建议字段：

- `case_id`
- `name`
- `input_data`
- `expected_output`（可选）
- `source`
- `description`（可选）
- `metadata`（可选）

### 2. CaseSource

用于区分测试用例来源：

- `USER`：用户提供；
- `AI_GENERATED`：AI 补充生成。

本轮不要求实现 AI 用例生成，只需要建立来源字段和数据模型。

### 3. CaseRun

表示某个测试用例的一次实际执行。

建议字段：

- `run_id`
- `case_id`
- `status`
- `execution_trace`
- `animation_trace`
- `actual_output`
- `expected_output`
- `error`
- `execution_metadata`

状态至少区分：

- `PENDING`
- `RUNNING`
- `SUCCESS`
- `FAILED`
- `ERROR`

注意：

TestCaseSpec 是输入描述。

CaseRun 是一次真实执行实例。

ExecutionTrace 是程序执行事实。

AnimationTrace 是基于执行事实转换得到的视觉步骤。

四者不能混为一谈。

### 4. 数据关系

建议采用以下关系：

```text
TestCaseSpec
    |
    | execute
    v
CaseRun
    |
    +------ ExecutionTrace
    |
    +------ AnimationTrace
    |
    +------ actual_output
```

每次执行都应该形成独立 CaseRun。

如果同一个 TestCaseSpec 被重新执行，应当生成新的 run_id，而不是覆盖原来的执行记录。

具体字段和类型可以根据现有代码适当调整，但必须保留上述职责边界。

## 四、M3-5.2：多测试用例执行管理

新增一个轻量的用例执行管理模块。

建议位置：

`algoviz/execution/case_runner.py`

具体路径可以根据现有项目结构调整。

职责：

1. 接收多个 TestCaseSpec；
2. 逐个执行用户提供的 AC 代码；
3. 每个用例独立创建 CaseRun；
4. 每个用例生成独立 ExecutionTrace；
5. 将每个 ExecutionTrace 转换为对应 AnimationTrace；
6. 保存每个用例的实际输出；
7. 如果提供 expected_output，进行结果比较；
8. 记录执行失败、异常和错误信息；
9. 返回完整的用例执行结果集合。

要求：

- 不同用例不能共享可变的 ExecutionTrace。
- 不同用例不能共享可变的 AnimationTrace。
- 某个用例执行失败，不能导致其他用例的结果被错误覆盖。
- 一个用例失败后，其他用例是否继续执行应当有明确策略，建议默认继续。
- 每个 CaseRun 都必须能追溯到原始 TestCaseSpec。
- 不得通过手工编造 AnimationTrace 来代替真实执行。

如果现有 M1 ExecutionEngine 已经能够执行代码，请直接复用，不要重新实现执行引擎。

本阶段仍然只支持当前已验证的 Two Sum 代码执行形态，不要扩展 Java、C++ 或 stdin。

## 五、M3-5.3：每个用例独立生成 AnimationTrace

这是本轮最重要的部分。

每个 CaseRun 必须拥有与自身 ExecutionTrace 对应的 AnimationTrace。

必须保证：

```text
Case 1
  ├── ExecutionTrace 1
  └── AnimationTrace 1

Case 2
  ├── ExecutionTrace 2
  └── AnimationTrace 2

Case 3
  ├── ExecutionTrace 3
  └── AnimationTrace 3
```

要求：

1. 每条 AnimationTrace 都来自对应的 ExecutionTrace；
2. 每个用例的 step 数量可以不同；
3. 每个用例的变量状态可以不同；
4. 每个用例的数组和哈希表状态可以不同；
5. 每个用例的最终结果可以不同；
6. 每个用例的代码执行行号必须正确；
7. 不能把一个用例的最后状态带到另一个用例。

特别注意 Two Sum 的不同执行路径。

至少考虑：

- 正常找到答案；
- 第一轮就找到答案；
- 最后一轮才找到答案；
- 遍历结束仍然找不到答案；
- 输入中存在重复数字；
- 空输入或单元素输入（如果现有代码和题目契约支持）。

对于不支持的输入，应记录明确的执行状态或错误，不得伪造成功轨迹。

## 六、M3-5.4：用例切换机制

新增一个轻量的 CaseManager 或 CaseRunStore。

建议职责：

- 保存 TestCaseSpec 列表；
- 保存对应 CaseRun；
- 根据 case_id 或 run_id 查找结果；
- 获取当前选中用例；
- 切换当前用例；
- 获取该用例对应的 ExecutionTrace 和 AnimationTrace。

切换用例时，必须满足：

1. 加载目标 CaseRun；
2. 加载该 CaseRun 对应的 AnimationTrace；
3. 将播放位置初始化到该轨迹的初始步骤；
4. 使用目标用例的状态更新现有视觉组件；
5. 更新代码高亮；
6. 更新数组、哈希表、变量；
7. 更新实际输出和执行状态；
8. 不得继续使用上一个用例的动画轨迹。

如果某个用例尚未执行，不允许将其伪装成已有动画。

### 特别重要：VisualPlan 不随用例切换

VisualPlan 描述视觉组件结构和布局。

CaseRun 描述某次执行。

因此：

```text
TwoSumVisualProfile
        |
        v
    VisualPlan
        |
        v
VisualAssembler
        |
        v
已装配的视觉组件
        |
        +------ CaseRun 1 的 AnimationTrace
        |
        +------ CaseRun 2 的 AnimationTrace
        |
        +------ CaseRun 3 的 AnimationTrace
```

切换用例时，只切换数据和轨迹，不应重复创建四个视觉组件。

原则上也不应重复创建 VisualPlan 和 VisualAssembler。

如果当前组件接口不支持重置或加载初始状态，可以增加最小必要的状态更新接口，但不要借机重写所有组件。

## 七、M3-5.5：TwoSumStage 改造

对现有 `TwoSumStage` 做最小改造。

目标：

增加类似以下接口：

```python
stage.load_case(case_run)
stage.reset()
stage.current_case_id
stage.current_step_index
```

具体接口可以按现有代码风格设计。

`load_case(case_run)` 至少需要：

1. 验证 CaseRun 是否拥有有效 AnimationTrace；
2. 替换当前动画轨迹；
3. 重置当前 step index；
4. 读取新轨迹的初始状态；
5. 更新 ArrayVisualizer；
6. 更新 HashMapVisualizer；
7. 更新 VariableVisualizer；
8. 更新 CodeVisualizer；
9. 清除上一用例遗留的高亮和状态。

必须验证：

从 Case 1 切换到 Case 2，再切回 Case 1，三次显示的状态都正确。

不能仅替换 `self.animation_trace`，却保留上一个用例的组件状态。

注意：

本轮只实现轨迹加载和切换，不实现教师控制播放器。

## 八、M3-5.6：测试用例管理的最小使用接口

本阶段不要求开发完整前端。

但需要提供一个可验证的最小调用方式。

例如：

```python
cases = [
    TestCaseSpec(
        case_id="case_1",
        name="正常查找",
        input_data={
            "nums": [2, 7, 11, 15],
            "target": 9
        },
        expected_output=[0, 1],
        source=CaseSource.USER,
    ),
    TestCaseSpec(
        case_id="case_2",
        name="第一轮命中",
        input_data={
            "nums": [3, 2, 4],
            "target": 5
        },
        expected_output=[0, 1],
        source=CaseSource.USER,
    ),
    TestCaseSpec(
        case_id="case_3",
        name="重复数字",
        input_data={
            "nums": [3, 3],
            "target": 6
        },
        expected_output=[0, 1],
        source=CaseSource.USER,
    ),
]
```

上面只是接口示意，具体用例应根据现有 Two Sum 实现的输入输出约定校验。

需要提供一个示例脚本，例如：

`scripts/m3_5_multi_case_demo.py`

运行后能够：

1. 创建多个测试用例；
2. 执行所有用例；
3. 打印每个用例的执行状态；
4. 打印 expected_output 和 actual_output；
5. 显示每个用例的 ExecutionTrace/AnimationTrace 步骤数量；
6. 演示切换不同 CaseRun；
7. 验证切换后当前视觉状态属于目标用例。

不要求本阶段开发可交互的 GUI。

## 九、测试要求

新增独立测试文件，例如：

`tests/test_m3_5_multi_case.py`

至少覆盖以下情况。

### 1. 数据模型

- TestCaseSpec 创建与字段校验；
- CaseSource 区分 USER 和 AI_GENERATED；
- CaseRun 状态正常；
- 不同 CaseRun 的 run_id 独立；
- 同一个用例重复执行时不覆盖旧记录。

### 2. 多用例执行

至少测试：

- 正常找到答案；
- 第一轮找到答案；
- 最后一轮找到答案；
- 找不到答案；
- 重复数字；
- 空输入或单元素输入（以题目契约为准）。

验证：
- actual_output 正确；
- expected_output 比较正确；
- 每个用例都有独立 ExecutionTrace；
- 每个用例都有对应 AnimationTrace；
- 不同用例 step 数量可以不同；
- 错误用例不会污染其他用例。

### 3. Trace 隔离

这是重点。

必须证明：

- Case 1 的 AnimationTrace 不会被 Case 2 覆盖；
- 切换 Case 2 不会继续播放 Case 1 的旧轨迹；
- 切回 Case 1 后，Case 1 的轨迹仍然完整；
- 两个 CaseRun 不共享可变的 VisualState；
- 当前状态与当前 case_id 对应。

### 4. VisualPlan 与组件复用

必须证明：

- 多个 CaseRun 使用同一个 VisualPlan；
- 切换用例不重复装配组件；
- 组件实例 ID 不变；
- 组件状态发生正确更新；
- 切换前后没有残留高亮或旧变量。

### 5. 回归测试

完整运行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

还需要运行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_tracers.py
```

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_m1_execution.py tests/test_m2_teaching.py
```

不得删除旧测试、降低断言或跳过测试来获得通过结果。
