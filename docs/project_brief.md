# AI Algorithm Video Factory
## 基于大语言模型的算法教学视频自动化生成系统设计方案

**项目类型：** AI Agent / 算法可视化 / 视频自动化生成

**核心目标：** 通过自然语言、伪代码或源代码输入，自动生成简洁、准确、风格统一的算法教学视频，并支持批量导出 MP4。

> **M4 工作台：** 启动 `.\.venv\Scripts\python.exe -m uvicorn algoviz.api.app:create_app --factory --host 127.0.0.1 --port 8000`，打开 `http://127.0.0.1:8000/`。  
> 新工作台提供 Two Sum 项目、代码、测试用例、真实执行、课堂播放与教学提示；旧视频工厂在 `/legacy`。详细说明见 `M4_IMPLEMENTATION_REPORT.md`。

# 一、项目背景与建设目标

## 1.1 项目背景

目前常见的算法可视化方式主要包括网页动画、PPT 动画和人工视频制作。这些方法虽然能够实现算法过程的动态展示，但通常需要人工编写动画代码、设计视觉元素、控制动画时间轴，制作效率较低。

随着大语言模型和 AI Agent 技术的发展，可以将算法理解、执行过程追踪、动画生成和视频合成整合到一个自动化工作流中。

本项目希望实现：

**输入算法描述 → AI 理解算法 → 程序执行并记录过程 → 自动生成动画 → 合成 MP4 视频。**

## 1.2 项目目标

系统需要满足以下要求：

| 项目 | 具体要求 |
|---|---|
| 输入方式 | 自然语言、伪代码、源代码 |
| 算法范围 | 排序、查找、树、图、动态规划 |
| 输出格式 | MP4 |
| 动画风格 | 简洁二维教学动画 |
| 生成方式 | 自动化、批量生成 |
| 教学内容 | 算法思想、执行步骤、代码高亮、复杂度分析 |
| 扩展能力 | 支持增加算法类型和动画模板 |

# 三、系统总体架构设计

## 3.1 整体架构

系统采用分层设计，将 AI 算法理解与实际算法执行分离。

```text
                  用户输入
                      |
          +-----------+-----------+
          |           |           |
       自然语言     伪代码      源代码
          |           |           |
          +-----------+-----------+
                      |
                AI 算法解析层
                      |
           算法识别与执行模型构建
                      |
              算法执行追踪层
                      |
           Animation Event JSON
                      |
             动画渲染引擎 Manim
                      |
             教学内容生成模块
              /             \
          字幕生成          TTS 配音
              \             /
               视频合成 FFmpeg
                      |
                 MP4 输出
                      |
                批量任务管理
```

## 3.2 核心设计原则

**不要让大模型直接生成每一帧动画。**

推荐将系统拆分为三个核心部分：

1. AI 负责理解算法、生成教学内容和辅助规划。
2. 算法执行器负责真正运行算法，并记录执行事件。
3. 动画引擎负责读取事件并进行可视化渲染。

这种设计可以避免 AI 凭空编造算法执行步骤。

# 四、算法执行追踪系统

这是整个项目最重要的模块。

不同算法具有不同的执行逻辑，但可以将其转换为统一的动画事件。

## 4.1 五类算法追踪器

| 算法类别 | 追踪器 | 需要记录的事件 |
|---|---|---|
| 排序 | SortTracer | 比较、交换、覆盖、完成 |
| 查找 | SearchTracer | 比较、中间位置、区间缩小、命中 |
| 树 | TreeTracer | 节点创建、访问、递归、旋转 |
| 图 | GraphTracer | 节点访问、边遍历、距离更新、路径确定 |
| 动态规划 | DPTracer | 状态初始化、状态转移、表格更新、回溯 |

## 4.2 排序算法示例

以冒泡排序为例：

初始数组：

`[5, 3, 8, 1]`

执行过程：

1. 比较 5 和 3。
2. 发现 5 大于 3，执行交换。
3. 比较 5 和 8。
4. 不需要交换。
5. 比较 8 和 1。
6. 执行交换。
7. 继续下一轮，直到排序完成。

动画引擎只需要识别以下事件：

| 事件 | 动画效果 |
|---|---|
| compare | 高亮两个元素 |
| swap | 两个元素交换位置 |
| visit | 高亮当前元素 |
| update | 修改元素内容 |
| complete | 展示最终结果 |

这样不同排序算法就可以共享同一套数组动画组件。

# 五、统一动画事件协议

建议设计一套统一的 Animation Event JSON 协议。

示例：

```json
{
  "metadata": {
    "algorithm": "bubble_sort",
    "title": "冒泡排序",
    "language": "python",
    "input": [5, 3, 8, 1]
  },
  "steps": [
    {
      "type": "compare",
      "targets": [0, 1],
      "description": "比较第一个和第二个元素"
    },
    {
      "type": "swap",
      "targets": [0, 1],
      "description": "交换两个元素"
    },
    {
      "type": "compare",
      "targets": [1, 2],
      "description": "继续比较相邻元素"
    }
  ]
}
```

正式版本建议增加以下字段：

- step_id：步骤编号。
- state_before：执行前状态。
- state_after：执行后状态。
- targets：当前操作对象。
- code_line：对应源代码行。
- description：教学解释。
- duration：动画持续时间。
- narration：对应配音内容。
- visual_action：具体视觉操作。

需要保证事件能够被完整重放，方便视频暂停、回放、错误定位和断点渲染。

# 六、三种输入方式的实现

## 6.1 自然语言输入

示例：

“请生成快速排序的教学视频，选择第一个元素作为 Pivot，使用数组 [8, 3, 5, 1, 9, 2]。”

处理流程：

1. AI 识别算法类型。
2. 提取算法参数。
3. 生成标准算法执行模型。
4. 选择对应追踪器。
5. 执行算法并记录事件。

## 6.2 伪代码输入

示例：

```text
BinarySearch(A, target):
    left = 0
    right = n - 1

    while left <= right:
        mid = (left + right) // 2

        if A[mid] == target:
            return mid
        else if A[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
```

处理流程：

1. AI 解析控制结构。
2. 建立执行模型。
3. 识别比较、赋值和循环事件。
4. 通过执行器运行。
5. 输出统一事件格式。

## 6.3 源代码输入

支持逐步扩展：

- Python
- Java
- C++

推荐采用 AST 解析、代码插桩、调试器等技术追踪程序运行。

需要区分：

**已知算法：** 识别算法类型，映射到对应追踪器，并使用用户代码和测试数据进行验证。

**自定义算法：** 使用程序分析和执行追踪获取真实运行过程，AI 辅助补充语义信息。

不应仅让 AI 阅读源代码后模拟执行。

对于不可信代码，需要使用隔离执行环境，限制 CPU、内存、执行时间、文件访问和网络权限。

# 七、技术栈选型

| 系统模块 | 推荐技术 | 主要用途 |
|---|---|---|
| AI 模型 | GPT API | 算法理解、讲解文案 |
| 后端 | Python + FastAPI | API 和任务调度 |
| 数据校验 | Pydantic | 事件协议验证 |
| 算法追踪 | Python | 记录真实执行过程 |
| 动画引擎 | Manim CE | 二维动画渲染 |
| 视频处理 | FFmpeg | 视频合成和编码 |
| 语音生成 | Edge TTS / OpenAI TTS | 配音 |
| 批量任务 | Celery + Redis | 并发任务管理 |
| 文件存储 | 本地存储 / MinIO | 视频与中间文件 |
| 元数据 | SQLite | 任务信息和状态 |

第一版不需要引入过多基础设施。

建议先使用 Python、Manim、FFmpeg 和 SQLite 完成最小可用版本，再逐步引入 FastAPI、Redis 和 Celery。

# 八、批量视频生成工作流

## 8.1 视频生成流程

```text
提交算法任务
      |
      v
解析输入内容
      |
      v
识别算法类型
      |
      v
选择执行追踪器
      |
      v
执行算法并验证结果
      |
      v
生成 Animation Event JSON
      |
      v
生成教学脚本和字幕
      |
      v
Manim 渲染动画
      |
      v
TTS 生成配音
      |
      v
FFmpeg 合成视频
      |
      v
质量检查
      |
      v
导出 MP4
```

## 8.2 任务管理

每个算法视频应作为独立任务。

建议包含以下状态：

- Pending：等待执行。
- Parsing：解析输入。
- Executing：算法执行。
- Rendering：动画渲染。
- Synthesizing：视频合成。
- Validating：质量检查。
- Completed：生成完成。
- Failed：任务失败。

单个任务失败时，只重试对应任务，不重新生成整个批次。

## 8.3 输出规范

建议统一：

| 项目 | 默认配置 |
|---|---|
| 视频格式 | MP4 |
| 视频编码 | H.264 |
| 分辨率 | 1920 × 1080 |
| 帧率 | 30 FPS |
| 画面比例 | 16:9 |
| 动画风格 | 简洁二维 |
| 字幕 | 中文字幕 |
| 配音 | 中文 |
| 背景 | 浅色或深色统一主题 |

# 九、视频教学内容规范

算法可视化不等于简单地录制程序执行过程。

为了保证批量生成的视频具有统一教学质量，建议每个视频采用固定结构。

1. **问题引入：** 说明算法解决什么问题。
2. **核心思想：** 通过简单图形解释算法原理。
3. **执行过程：** 逐步展示关键操作。
4. **代码对应：** 高亮当前执行的代码行。
5. **复杂度分析：** 展示时间复杂度和空间复杂度。
6. **总结：** 归纳算法特点和适用场景。

AI 可以负责讲解文案，但复杂度等技术结论应从算法定义和验证数据中获取，不能完全依赖模型自由生成。

# 十、分阶段开发计划

## 第一阶段：最小可用版本（MVP）

**目标：完成从自然语言输入到 MP4 输出的完整流程。**

优先支持：

- 冒泡排序
- 快速排序
- 归并排序
- 二分查找

开发内容：

1. 搭建 Python 和 Manim 环境。
2. 设计统一事件协议。
3. 实现数组追踪器。
4. 实现数组动画模板。
5. 接入 AI 算法解析。
6. 生成教学字幕。
7. 接入 TTS 和 FFmpeg。

验收标准：

连续提交 10 组不同测试数据，生成的视频能够正常播放，排序和查找过程正确，动画与实际执行结果一致。

## 第二阶段：扩展算法范围

新增：

- 二叉树遍历。
- 二叉搜索树。
- BFS。
- DFS。
- Dijkstra。
- 0-1 背包。
- 最长公共子序列。

开发内容：

1. 实现树结构追踪器。
2. 实现图结构追踪器。
3. 实现动态规划追踪器。
4. 开发树、图、矩阵动画组件。
5. 增加伪代码输入。

验收标准：

五类算法均能通过统一事件协议完成动画生成。

## 第三阶段：源代码输入与批量生产

开发内容：

1. 支持 Python、Java、C++。
2. 增加 AST 分析和代码插桩。
3. 增加安全隔离执行环境。
4. 接入 Celery 和 Redis。
5. 实现批量任务管理。
6. 实现失败重试。
7. 增加视频预览和归档。
8. 支持多语言字幕和配音。

验收标准：

一次提交几十个算法任务，能够独立执行、检查、重试和导出。

# 十一、风险与解决方案

| 风险 | 解决方案 |
|---|---|
| AI 生成错误算法逻辑 | 真实执行算法并进行测试 |
| 动画步骤不完整 | 事件协议记录完整状态 |
| 动画与配音不同步 | 统一时间轴管理 |
| 不同算法布局不一致 | 统一视觉规范和组件库 |
| 源代码执行存在安全风险 | 使用容器隔离和资源限制 |
| 批量任务失败 | 任务队列、日志和重试 |
| 动画代码生成失败 | 固定模板优先，AI 生成作为补充 |

# 十二、最终技术选型与实施建议

推荐组合：

| 组件 | 选择 |
|---|---|
| 开源项目参考 | Algo LightsOn |
| AI 工作流 | GPT API + Manim Video Skill |
| 动画引擎 | Manim CE |
| 算法执行 | Python Tracers |
| 数据协议 | Pydantic + JSON |
| 视频合成 | FFmpeg |
| 后端 | FastAPI |
| 批量任务 | Celery + Redis |
| 数据存储 | SQLite / MinIO |

## 核心实施原则

不要一开始就开发一个支持所有算法、所有语言和所有动画效果的复杂系统。

应该先实现：

**快速排序自然语言输入 → 算法执行追踪 → Animation Event JSON → Manim 动画 → 中文字幕与配音 → MP4 输出。**

以这个流程作为第一个完整验收样例。

如果能够稳定生成正确、清晰、风格统一的快速排序视频，再将数组动画组件扩展到其他排序和查找算法，随后开发树、图和动态规划组件。

最终形成一个可复用的算法教学视频自动化生产系统。
